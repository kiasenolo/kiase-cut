# 聲音轉數值（peak to value）與聲音節點傳參數：規劃草案（2026-11-25）

狀態：**等你確認，還沒實作。** 接在 [audio-page.md](audio-page.md) 之後。現況是讀程式得出的，沒有實際開程式操作。

## 1. 已確認

| 問題 | 回答 |
| --- | --- |
| 節點給參數 | 要能用線把數值傳給參數。要把畫面節點的數學類節點搬到聲音節點，接受工作量較大 |
| 框選什麼 | 在頻譜上拉框：左右是頻段，下緣音量＝0，上緣＝1 |
| 聽哪裡 | 軌道、bus、Master，經過效果和推桿之後。靜音的軌道也要能驅動 |
| 驅動什麼 | 畫面參數和聲音參數都要 |

## 2. 現況

| 位置 | 現在怎麼給參數 | 問題 |
| --- | --- | --- |
| 聲音節點圖 | 接點只有立體聲 | 節點之間不能傳數值 |
| 聲音節點上的右鍵綁定 | 直接綁全局參數或表達式 | 節點上的數字和曲線仍顯示原本的值，只多一個「=」（`sound_node_editor.show_values` 沒套用全局參數；效果鏈面板有套用）。看起來像沒生效 |
| 畫面節點圖 | 參數輸入 → 效果面板右鍵綁定 | 分兩步。這次沒有要改 |
| 聲音 → 畫面 | 只有音訊視覺化畫自己的圖 | 沒有通用的方法 |

可以沿用的部分：

- **全局參數**已經有「用別的東西當數值來源」的位置（LFO），畫面和聲音兩邊都已經能綁全局參數。
- **`viz.py`** 有 attack / decay 和跳轉後結果相同的做法。但它拿的是效果**之前**的聲音（不經過效果鏈和 bus），所以只能借頻譜函式，聲音來源要走 `soundgraph.Engine`。它的 `band_levels` 取平均能量並做高頻加成，和這裡要的「峰值」不同。
- **`sound_visuals.Analysis`** 的 dB 刻度：框選畫面和實際量測用同一套，看到什麼就量到什麼。

## 3. peak to value 放在哪裡

| 方案 | 優點 | 缺點 |
| --- | --- | --- |
| A. 畫面節點圖裡加一個來源節點 | 在節點圖裡看得到來源 | 畫面節點的數值其實是整張圖（接參數時從畫面中央讀回），多一種要分析聲音的來源會讓系統更雜。每個節點圖要各放一個、各框一次。位置、縮放、一般效果、聲音參數都用不到 |
| **B. 全局參數的一種數值來源（建議）** | 畫面節點系統**一個節點都不加**。框一次，到處用。現有的右鍵綁定、映射、表達式直接能用 | 要到全局參數架設定。節點圖裡看不到它在聽哪裡 |
| C. 獨立的「控制器」面板 | 可以做得很大 | 多一套清單、命名和綁定介面，做的事和全局參數一樣 |
| D. 聲音節點圖裡加「送出到全局參數」節點 | 送出前能先用數學節點加工 | 全局參數變成依賴某條效果鏈裡的節點圖，藏得深，循環也難檢查 |

**建議 B**，再加上聲音節點圖裡的一個節點：

- **全局參數「聲音」來源**：跨系統用（畫面、其他聲音效果鏈）。
- **聲音節點「電平 → 數值」**：接一條聲音線進去，出一條數值線，只在這個節點圖裡用。這是第 6 節接線系統的一部分，不影響畫面節點。
- 兩者共用同一套計算（`soundmeter.py`）和同一個框選元件。

D 先不做。之後真的需要「加工後的數值給畫面用」再討論（簡單的加工用全局參數的表達式就夠）。

## 4. 全局參數的「聲音」來源

### 介面

- 數字類型的參數列，在 ✎（表達式）、∿（LFO）旁邊多一個聲音按鈕。聲音和 LFO 二選一。
- 對話框內容：
  - 來源：時間線或複合片段 → 軌道、bus 或 Master
  - 頻譜，加上可拖曳的框（四邊都能拖），框內顯示目前的峰值
  - 啟動、釋放（預設 0 ms、150 ms）
  - 0～1 的歷史曲線和目前數值
- 輸出固定 0～1。要換成其他範圍或反過來，用現有的映射或表達式。參數的表達式照舊套在來源之後（`input` 就是 0～1 的值）。

### 資料格式

```json
{"id": "...", "name": "kick", "value": 0.0,
 "sound": {"level": "<時間線或複合片段 id>", "channel": "<軌道 / bus id 或 master>",
           "lo_hz": 40, "hi_hz": 120, "floor_db": -36, "top_db": -6,
           "attack": 0.0, "release": 0.15}}
```

### 怎麼算

1. 取框內頻率的**最大值**（dB），下緣對應 0、上緣對應 1，超出的部分夾住。分析窗 2048 點（約 43 ms），中心對準該時間點。
2. 每 512 取樣（約 10.7 ms，和聲音引擎的區塊相同）算一個值。
3. 從時間線開頭套啟動 / 釋放。

框很寬時，它量的是框內最強的那個頻率，不是波形的峰值。

### 靜音、獨奏、參考軌

- **被聽的那一條**：效果、推桿、聲像照算，**不管它的靜音和獨奏**。所以靜音的大鼓觸發軌能用。Master 另外包含主音量。
- **送進它的其他軌道**：照靜音設定（靜音的不會出現在 bus 裡）。
- **獨奏**一律不影響分析。否則按一下獨奏，畫面就跟著變。
- 參考軌被選為來源時照樣聽得到，預覽和匯出相同。

## 5. 預覽和匯出一致

不邊播邊算，改成**先把整條曲線算好，之後只查表**。

- 分析時，從時間線開頭用 `soundgraph.Engine` 完整跑一次，取出該條的聲音。因此跳到任意時間點、從中間匯出、`python -m kiasecut render` 的 `--from / --to`，拿到的值都和從頭播放相同。也不受引擎跳轉時「只往前預跑一段」的誤差影響。
- 快取分兩層：
  - **該條的聲音**（單聲道，每分鐘約 6 MB）：只在上游內容改變時重算。
  - **0～1 曲線**：拖框、改啟動 / 釋放時只重算這一層，不用重跑引擎。
- 快取鍵包含上游的片段、效果、接線、用到的參數、素材檔案時間和程式版本。
- 預覽時在背景分析。算完前沿用舊曲線（第一次為 0），狀態列顯示「分析聲音中」。連續編輯時等停手再重算。
- 匯出和 CLI 一定等分析完成。找不到來源或分析失敗時匯出報錯；CLI 加 `--allow-errors` 才用 0 繼續。
- `rack.values()` 只做查表，介面、畫面渲染、聲音執行緒都能呼叫。
- 長專案、重效果時的分析時間**還沒測過**，第 1 階段先量。

### 複合片段

- 來源可以選任何一層裡的軌道或 bus。該層**單獨沿自己的時間**分析。
- 讀值用的時間，和全局參數的關鍵幀、LFO 相同：目前渲染的那條時間線的時間。
- 結果：來源和使用處在同一層時完全對得上。複合片段 A 裡的聲音，在外層讀取時**不會**跟著 A 這個片段在外層的位置或速度平移。多次使用 A 時也無法決定該跟哪一個。
- 常見做法是來源選最外層的時間線。要讓它跟著複合片段位置走，需要另外設計，這次不做。

### 循環依賴

聲音參數可以跟隨聲音來源，例如大鼓響時把 bass 壓低。但下面這種會算不出來：

> 參數 P 聽 bus A，而 bus A 的某個效果（或送進 bus A 的某一路）又用了 P。

- 檢查範圍：被聽那條的所有上游，包括片段和各軌的效果、接線、側鏈、外部輸入、裡面的複合片段；以及它們讀到的全局參數、那些參數的表達式引用，再遞迴到其他聲音來源。
- 沒有循環時，按依賴順序分析（先算 Q，再算用到 Q 的那一路）。
- 綁定時會造成循環就拒絕，並寫出經過的路徑。
- 之後改接線才形成循環（或手改專案檔）時：迴圈裡的聲音來源讀 0，參數列顯示警告，匯出報錯。
- 聽 Master 的參數只能給畫面用，或給不在這一層訊號路徑上的聲音。
- 畫面數值目前不會流向聲音，所以只需要檢查聲音和全局參數。

## 6. 聲音節點圖傳數值

### 接線

- 新的接點類型「數值」，顏色和聲音接點不同。數值只能接數值，聲音只能接聲音。
- 節點的每個數字和選單參數列，左邊多一個輸入點。接上後欄位顯示即時數值，不能拖曳。
- 優先順序：**接線 > 全局參數綁定 / 表達式 > 關鍵幀或固定值**。拔線後恢復原本的值。
- 接進來的數值直接當參數值，超出範圍就夾住（和畫面節點一樣）。要換範圍用「映射範圍」，另外加「對數」模式給頻率類參數。
- 數值每個區塊（約 10.7 ms）更新一次，和現在的關鍵幀相同。**不做音訊速率調變。**
- 經過有延遲的效果（例如限幅器）算出的數值，要和聲音一樣對齊時間。
- 存檔：連線的輸入欄位，聲音用原本的編號，數值用 `"param:thr"` 這種名稱。舊節點圖不用轉換。

### 要搬的節點

| 批次 | 節點 |
| --- | --- |
| 第一批 | 數值、全局參數（讀一個參數）、電平 → 數值、數學（41 種運算）、映射範圍、限制 |
| 第二批 | 浮點曲線、混合（浮點）、場景時間（秒、進度）、整數、布林、選單、切換 / 索引切換 / 選單切換（只切數值） |
| 不搬 | 向量類（合併 / 分離 XYZ、向量數學等）：聲音參數都是單一數字。向量類的全局參數，在「全局參數」節點選要哪個分量 |

- 畫面版的運算寫在 GLSL 裡，聲音版要用 Python 重寫一份。選項名稱和順序直接讀畫面節點的定義，另外寫測試比對兩邊的結果（含除以 0、負數次方等邊界）。
- 「電平 → 數值」的框和第 4 節相同。差別是節點圖會即時執行，只能看過去的聲音，反應會比全局版本晚約 20 ms。跳轉後靠引擎的預跑回復狀態，釋放時間非常長時可能和從頭播有極小差異。
- 節點圖本身不能接成迴圈（現有規則，數值線一起檢查）。
- LFO 節點之前延後了，這次也不列入。聲音節點仍可透過全局參數的 LFO 取得。
